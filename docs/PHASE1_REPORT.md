## 4. 技术选择与规格处理

- React + TypeScript + Vite，严格类型检查，包括测试代码；未使用 `any`、类型检查关闭或跳过测试来规避错误。
- FullCalendar 6.1.22 免费标准插件；没有 Premium、资源 Timeline 或付费服务。
- Dexie 4.4.6 + Zod 3.25.76。React Context 配合 Dexie `liveQuery` 已满足此规模，未另加 Zustand。
- 使用原生表单、`dialog`、CSS 变量、Lucide 图标，减少组件和样式框架依赖。相对构建路径为后续 Pages 子目录部署保留空间。
- 使用原生 Date/Intl，不额外引入日期库。单次事件的模型较简单，配合本地往返与真实日期校验即可覆盖本阶段；重复规则留待 Phase 2 独立设计。
- 规格中的“全天另行显式建模”优先于草案的统一 startAt/endAt：正式时间块采用全天日期区间或普通 UTC 区间的联合类型。
- 用户任务已允许先完成安全替换导入，因此没有实现 PRODUCT_SPEC 所建议的合并导入。
- Phase 4 才做完整 PWA 安装，但 Phase 1 要求断网刷新可用，因此只实现必要的生产静态缓存，无 Manifest、安装入口、更新管理界面或通知。
- 显示时区固定跟随浏览器；导入文件的 `settings.timeZone` 和时间块创建时区作为元数据保留，不强行将其他设备的显示时区套用到本机。

## 5. 数据结构与事务

数据库：当前来源的 `polar-schedule`，Dexie 结构版本 1。

| 表 | 关键内容 |
| --- | --- |
| lists | 清单、图标、颜色、order、archived、revision 和时间戳 |
| tasks | listId、任务内容、status、priority、可选 dueDate/completedAt、order 和元数据 |
| scheduleBlocks | type=event 的内容，或 type=task 的 taskId；时间范围与元数据 |
| metadata | schemaVersion=1、Settings、根 updatedAt |
| tombstones | `[entityType + id]` 唯一删除记录与 deletedAt |
| backups | 最近 3 次完整替换前的已验证快照；创建时间单调排序 |

时间块四种合法组合为 event/task × timed/allDay。普通时间为 UTC ISO 8601，截止日期为无时区日期，全天为 `[startDate, endDate)`；表单显示的全天结束日包含当天，保存时增加一天。

每次操作在读写事务中读取并校验当前快照，应用变更，再校验并写入。多标签页写操作由 IndexedDB 事务串行协调。没有服务端、同步队列或远端请求。

- 删除清单：将其任务迁移到收集箱、更新元数据、移除隐藏引用、删除清单并写墓碑；安排保留。
- 删除任务：存在关联时要求确认；任务、关联时间块和墓碑同一事务处理。
- 替换导入：在事务前验证输入；事务内备份旧数据，再清表写入新快照。任意写入失败整体回滚。
- 拖动写入失败时调用 FullCalendar revert，不用未经持久化的显示结果冒充成功。
- 默认启动不清空已有数据库；若检测到损坏或缺元数据，停止初始化并提示保留原数据。
- 第一版没有历史结构需要迁移；保留 Dexie version(1)、JSON schemaVersion 和实体 revision，未知版本明确拒绝。

## 7. 未完成项与已知限制

以下属于明确延后或实机验收边界，无已知阻塞当前本地主要流程的问题：

- JSON 仅支持完整替换，合并导入后续实现。
- 没有 GitHub 认证/同步、冲突合并、后端、重复日程、子任务/高级标签、统计、提醒、多用户、外部日历或完整 PWA 安装/Pages 发布。
- 时区跟随浏览器，尚无任意 IANA 时区选择器；DST 回拨重复本地时间采用浏览器较早一次，没有选择第二次的界面。
- 每次事务读取、验证完整快照并批量写回，适合个人规模；超大历史数据的增量处理与性能压测尚未做。导入文件限制 30 MB。
- 清单排序通过上下按钮，未实现清单本身拖拽排序；任务支持稳定 order 与上下按钮。
- 浏览器写入本身是异步的；用户须等待“正在保存”结束。离开保护不能抵御强制结束进程或突然断电。
- 离线首次访问需要先在线缓存生产构建；开发服务器不提供离线页面壳。缓存/Service Worker 需要 HTTPS 或 localhost 类可信来源。旧页面关闭后才激活新版本缓存。
- 本地存储按浏览器与来源隔离；换域名、端口或浏览器需 JSON 迁移。清理浏览器数据会同时清除数据库和内部备份。
- 已验证 Windows Chromium 和手机/平板宽度，**没有将模拟宽度等同于真实 Safari 或触摸设备测试**。浏览器配额/系统回收、长期稳定性、全屏幕阅读器流程仍未完成实机覆盖。
