## 1. P0：颜色选择器全站统一——新增需求，必须重点处理

### 1.1 真实问题

用户的截图显示：

- “标签颜色”当前只是一个**没有统一圆角与边框的方形色块**，点击后弹出 Edge/Chromium 原生的大块方形 RGB 颜色面板；
- “日程颜色”也只是独立、方正的小矩形；
- 两者与应用整体的紫色系、圆角卡片、按钮和弹层语言不一致，且原生颜色面板位置/大小及深浅主题不可控。

**注意：给 `<input type="color">` 加 `border-radius` 只能改变按钮外观，通常不能统一操作系统/浏览器原生颜色弹窗。不能把这个 CSS 小补丁作为完成。**

### 1.2 产品交互与视觉设计

创建一个真正可复用的 **`ColorPicker`** 组件，供至少以下场景调用：

- 标签新建/编辑颜色；
- 清单新建/编辑颜色；
- 独立日程/事件颜色；
- 检查项目内其他使用浏览器原生 `<input type="color">` 或孤立色块的场景，一并复用，避免漏项。

推荐 UI：

- 表单里显示**有圆角的颜色按钮**（例如带色点/小色块与当前颜色标识），与输入框、按钮高度协调；禁止继续暴露裸方形 swatch 作为主要入口；
- 点击后显示 **项目自己控制样式的轻量浮层**：顶部当前颜色预览、下方常用配色（包括当前紫色品牌色及多种区分清晰的颜色），支持选中高亮；
- 允许真正自定义颜色，而不是只有预设。可以采用经过评估的**体积小、免费、许可兼容、支持 React 的可访问颜色选择组件/库**来提供色相、饱和度/亮度调节；如自己实现，则必须正确处理 Pointer Events、触屏与键盘，不得只写一个看似能拖动但操作不完整的色板；
- 提供 `#RRGGBB` 十六进制输入（校验合法格式）和明确的当前选择状态；可选择预览、确认/取消语义，取消不应写入数据；若原表单有统一保存按钮，颜色暂存应遵守该表单的既有保存规则，不得点击颜色就悄悄覆盖用户未保存的内容；
- 弹层圆角、阴影、边框、间距、排版与主题统一；**不得再弹出截图里的系统原生方形 RGB 面板作为默认交互**；
- 浅色与深色都应显示正常，颜色对比合理；清单与任务的颜色仍保持原有语义，不强行调整用户已有色值；
- 浮层需要跟随锚点或自动调整位置，位于长 Dialog 的底部时不得被裁切；根据情况使用 portal 与 collision detection，但注意层级、焦点管理和点击外部关闭行为；
- 支持 Escape 关闭、键盘选择、可访问名称/状态、鼠标及触屏；不应因点色块触发上层表单提交或意外关闭整个弹窗。

**技术约束：** 数据持久化颜色格式尽可能保持现有兼容形式（例如 `#RRGGBB`），此需求正常情况下**不应触发数据库 schema 迁移**。如果依赖新包，说明维护/许可证/体积/无障碍取舍，并更新锁文件。禁止引入大型 UI 框架只为颜色选择。

### 1.3 颜色验收场景

1. 标签、清单、独立日程三个入口 UI 完全统一，主触发控件都是圆角；没有截图中的原生系统方形 RGB 面板。
2. 能点预设颜色，也能自定义非预设颜色，能输入合法 HEX；无效 HEX 不保存并有提示。
3. 已存颜色重开编辑正确回显；取消不改变已有色值，确认并保存后刷新/重新打开仍保留。
4. 颜色更改后清单/标签/日历显示映射立即正确更新；不会串改其他实体。
5. 在靠近弹窗底部、右边缘、390px 手机宽度、深色模式下打开，浮层不越界、不被遮挡、可完整操作。
6. 屏幕阅读器/键盘可访问主入口、选色、确认和关闭，Esc/焦点恢复正常。

## 2. P0：完成一次执行后，日历有明显且一致的反馈

Phase 2.1 **已实现**单次执行完成状态和基本 □/✓ 符号，不要另加一套打卡数据。当前待改的是**呈现不够明显**：用户希望回看月/周/日历时一眼分辨。

- 对同一 Task 的每个 task 型时间块读取已有 `executionStatus`，已完成采用 ✓ + 清晰可区分的弱化/背景/描边/标签方案，不得只靠 hover、颜色极浅或几像素图标。
- 日、周、月三个视图的语义统一；深浅主题均有足够可读性，缩小后的月格仍能看出“已完成”。
- 点击已完成安排可直接编辑/撤销本次完成，状态立即同步；其他安排和父任务总状态不变化。
- 任务父状态为 `done` 时不允许推断全部子安排完成；独立 event 不伪装为有打卡状态的 Task。
- 完成不应隐式删除日历时间块、不改变原时间范围；跨标签页、离线刷新、v3 JSON 导出/导入保留原记录。

## 3. P0：周/日视图的重叠展示必须“能看懂、能点到”，而非只在代码里并列

**之前的 `slotEventOverlap=false`、`+N`、背景标记是基础，并未满足用户的视觉要求。**

### 3.1 普通时间块

- 复现典型场景：长 08:00—23:00、短 08:30—09:45、另一个 08:30—10:00；同时测试两条、三条及五条以上重叠。
- 优先保护短块的可发现性与点击区域，避免细到难以点击的竖条、被完全盖住的条目、标题按单个汉字竖排或标签裁切。
- 宽度足够时布局整齐、间距合理；空间不足时**清晰显示摘要与 `+N` 可操作入口**，完整条目列表可查看时间、标题、类型、状态和编辑入口。
- 适度缩小边框、间距、装饰，避免“每个事件套很多框”和格内塞过多说明文字；深色模式也要协调。
- 不为了视觉好看而篡改实际时间、合并不同数据、隐藏冲突或禁止重叠。

### 3.2 背景安排

- 保留 Phase 2 已有背景属性，但不要把背景/分级作为日常默认交互的中心。
- 原生背景可不捕获鼠标；**独立可发现的背景标记及详情列表必须保留且易用**。测试短背景+长前景、长背景+短前景，不能出现短背景“消失”的体验。
- 背景范围参与真实冲突判断；其编辑入口不能挡住前景时间块的鼠标点击、移动或拉伸。
- 若现有 `+N` 标记显得拥挤，请精简其外观与位置，避免事件周围层层叠加奇怪色条。

## 4. P0：月视图按“直观总览”重排，全部应显示的事件直接成为可见条目

- **月视图彻底取消背景/覆盖分级视觉算法**：即使事件在周/日视图采用 `display=background`，月视图也将其投影为普通可点击事件条目（仅是显示方式不同，**不改持久化 display 属性**）。
- 任务安排、独立日程、背景安排、重复系列实例、跨日与全天事件都应出现；“全部”以用户清单可见性/归档/筛选规则为前提，不能绕过明确隐藏的清单。
- 每个条目简单表现时间（适用时）+ 完整或合理截断的标题 + 完成状态；修正当前月格里左边框/符号贴着格线导致标题挤压、残缺（例如圆弧、括号或细竖条）的表现。
- 每日事件过多时使用原生日历或明确的 `+N 更多`，打开后有**所有**应显示条目，不允许静默丢失；月格整齐、留白合理，不硬塞周视图冲突图层。
- 不要让月视图为了显露“背景”而新增第二个重复事件副本，造成条目数与真实数据不一致。

## 5. P0：月/周视图点击日期，弹出当天快速预览

这是**新功能**，此前 Phase 2.1 还没有完成。

- 月视图点击**日期数字/标题**（如“20日”）弹出当日预览；周视图点击顶部“周二 20”弹出当日预览；点击日期不是新建事件。
- **明确区分点击目标**：点击空白月格/周时间网格仍保留新建日程、拖选、拖拽等操作；点击已存在的事件仍直接进入事件/本次执行安排编辑。处理 click/mousedown/pointerdown 冒泡，避免一次操作打开两个弹窗。
- 桌面显示靠近触发日期的轻量 popover / dialog（可根据尺寸居中），手机为适合触摸的底部抽屉或响应式 dialog。
- 预览内容：日期、星期、全天安排、当天普通/背景/任务执行/重复实例；按时间排序，显示起止时间、完整标题、清单颜色、本次完成标记（适用时）。跨日长事件须显示当天实际交集时段及必要的“跨日”语义。
- 重叠事件在预览里**按列表直观显示**，不复制时间轴的窄并列算法；无内容显示简洁空状态。
- 点击预览条目打开**当前已有**的事件编辑或本次任务安排编辑；避免重复实现父任务/时间块映射。
- 底部提供明确按钮：**「查看完整日视图 →」**。点击后关闭弹层、把主视图切换到所选日期的日视图，标题和日历焦点同步更新，数据不变。
- 支持点击外部、Esc 关闭、焦点恢复、键盘打开；对较长列表仅在弹层内合理滚动，不能制造多个奇怪页面滚动条。

## 6. P0：顶部支持直接跳转任意日期/月份/所在周

- 保留前/后导航及「今天」，在附近加入清晰且紧凑的「跳转」按钮或日期入口。
- **复用 Phase 2.1 已有 React DayPicker 日期选择组件能力**，不要重新写一个月历。支持选日期，并提供有效的键盘手动输入；建议 `YYYY-MM-DD`，月视图可额外支持 `YYYY-MM`。
- 日视图选某天 → 跳当天；周视图选某天 → 跳到其所在周（使用用户设置的周起始日）；月视图选某天/某月 → 跳到该月。
- 处理 2 月闰日、跨年、非法日期、时区显示；不能因为 UTC 解析而跳到前/后一天。跳转后的标题、选中日期和日历数据必须一致。
- 弹层风格同日期时间选择器，支持 Esc、焦点管理、手机操作。

## 7. P0：月视图滚轮和滚动容器修复

用户反馈月视图中无法自然用滚轮上下滚动。请先查清真正原因（`overflow`、容器高度、内部日历 scroller、滚动链、事件拦截等），不要随便加一条滚动监听蒙混过关。

- 内容超出视口时，鼠标滚轮和触控板能够自然滚动**正确的容器**；若月历全部放得下，不要求为了制造滚轮效果而强行出现滚动条。
- 不允许滚轮默认跳月，除非未来用户明确选择这种快捷方式；不能因 hover 到日格就阻止自然滚动。
- 减少无意义的 FullCalendar 内外双重滚动条；避免底部“本段安排 / 背景安排”区域卡住滚轮、遮住月格内容。
- 验证 5/6 行月份、不同窗口高度、缩放、月格多个事件、侧栏开关，以及 `+N`、日期预览弹窗内部滚动。

## 8. P1：统一日期时间组件，补齐遗漏但不重新发明

**Phase 2.1 报告明确说明已经实现 React DayPicker + 月历、24 小时、精确分钟和键盘输入。** 所以本节是清查**仍遗留原生、不一致、难操作的入口**：

- 原生 `datetime-local`/`date` 若仍是某些功能的主要路径，要接入已有统一组件或提供一致的入口；保留键盘精确输入作为补充。

- 浅/深模式、390px 宽度、弹层靠近边界、Esc/焦点恢复、确认/取消均检查。
- 不因重复组件改造而引入第二套日期存储/转换规则。

用户截图里有**三个类似设置的入口**：顶栏右侧滑杆图标、左侧“工作空间”标题旁滑杆图标、左下角“设置与数据备份”。必须收敛。

- 不要仅凭“入口个数”砍掉已有操作，追求**一个全局设置入口 + 就近局部操作**。

## 10. P1：视觉一致性与更轻的界面布局

- 修复**主日历只有左上角圆、其他角方**的效果：检查外层 card、FullCalendar 表格/边框/滚动区、clip/overflow 和底部扩展列表，用统一容器策略处理四角，不要在单一角上叠 CSS 补丁。

- 解决设置对话框中**横向滚动条**：修复内容过宽的真正原因，不能简单把超出部分藏起来导致被截断；手机端同样无横向溢出。

## 12. 强制验收：真实浏览器交互 + 截图比对 + 回归

### 12.1 必测交互

1. **颜色统一**：标签、清单、日程色块外观一致；自定义色/预设色/HEX、确认/取消、保存回显、深色、390px、弹层靠底部、键盘和 Esc；不再默认出现原生大方形 RGB 选择面板。
2. **逐段完成**：一个 Task 在周一/周二各一块；完成周一后日/周/月视图立即明显变化，周二和父任务不变；撤销完成/改时/刷新/导出导入状态正确。
3. **重叠与背景**：长普通+短普通+第三块、短背景+长前景、长背景+短前景、五项重叠；有明确的全部条目入口、可点击编辑，不被盖住，且视觉不拥挤。
4. **月视图事件**：任务、普通 event、背景 event、全天/跨日/重复实例均以普通月事件可见且可点；`+N` 显示正确，遵守显隐规则；避免残缺左边框/窄符号。
5. **日期预览**：月视图点击“20日”、周视图点击“周二 20”，弹出正确日期全部安排；能点开本次编辑，并能一键跳该日日视图。点击月/周空白处仍走新建日程，事件点击不会同时触发日期预览。
6. **顶部快速跳转**：到其他年份、跨年周、闰日、`YYYY-MM-DD`、月选择、非法日期；周起始日设置影响周定位。
7. **滚轮**：月视图在较矮窗口或有较多日程时滚轮能自然滚动；内容放得下时没有假滚动；侧栏与浮层滚动互不干扰。
8. **日期时间弹层**：新建/编辑、任务本次/截止、重复规则相关日期、跳转共用一致体验；精确分钟、跨日、无效时间和 Esc 正确。
9. **设置与外观**：唯一全局设置入口；旧局部功能仍在；日历四角一致、设置面板无横向滚动条；1440px、768px、390px 和浅深主题可用。
10. **基础回归**：右侧任务拖入周/日/月、时间块拖动/拉伸/删除、背景管理、重复系列单次/整体编辑、子任务/标签、撤销、离线刷新和 JSON 恢复均未破坏。
11. **迁移保护**：在隔离测试浏览器中以 v2 数据升级到当前 v3，再打开新版 UI，核实 ID、单次完成字段、重复系列、备份、标签和设置仍在；真实用户数据未经触碰。
