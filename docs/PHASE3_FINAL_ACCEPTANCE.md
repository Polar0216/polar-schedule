# Phase 3 最后一次界面验收（约 5–10 分钟）

自动化结果见 [PHASE3_REPORT.md](PHASE3_REPORT.md)。以下留给用户自己的浏览器/设备，不需要修改脚本、手动调用 API 或初始化仓库。

1. 在项目目录执行 `npm run build`、`npm run preview -- --port 4173 --strictPort`（已有预览就直接使用）。打开原来的 `http://127.0.0.1:4173/`，联网关闭旧标签再重开以更新页面。不要清站点数据。先在「设置与数据 → 数据备份与恢复」导出完整 JSON。
2. 点同一设置内的「GitHub 同步」。确认标记为私有测试环境，目标为 `Polar0216/polar-schedule-data-test`，main / `data/polar-schedule.json`。正式数据仓库不参与此阶段。
3. 自己将测试 PAT 粘贴到网页授权框一次；可信个人设备可勾选「记住此设备」，再点验证连接。该模式允许浏览器持有可用凭据，不防恶意扩展或同源脚本；到期需要重新授权。开发者未将外部临时 PAT 放入你的浏览器。
4. 阅读首次预览并导出预览两端 JSON，确认数据归属再选本地创建/替换，或备份后采用远端。已有远端与本地都非空时，选择一端代表整份采用，不能当作自动合并。
5. 编辑一条任务，看到本地保存、待同步，再看到同步成功。打开 [私有测试仓库](https://github.com/Polar0216/polar-schedule-data-test) 查看应用文件与提交；隔离自动化测试文件在 `data/phase3-e2e/`，与应用文件分开。刷新/关闭重开检查自动连接。
6. 如有第二设备或隔离浏览器，在该设备授权并首次采用远端；两边断网改同一任务，依次联网同步。第二端应停在冲突，先导出两端，再选保留本地/远端并确认。不同任务的更改应自动合并。没有第二设备可暂跳过，自动化已模拟两个隔离浏览器。
7. 最后可点「断开并清除本设备凭据」，检查本地任务与安排仍在。此操作不撤销 GitHub 端 PAT；测试结束后可自行在 GitHub 撤销短期令牌。无需访问正式仓库。

若出现授权过期、限流或网络失败，先继续本地编辑并导出 JSON，在界面所示时间后重试或重新授权。不要通过清库、重建仓库或扩大令牌权限来排错。
