## 2. 两个 P0 问题：证据、原因与处理

### 2.1 右侧任务拖拽

调查了原有 `Draggable` 初始化、容器挂载、`itemSelector`、`create:false`、`drop`、任务 ID 映射、卡片点击/完成、层级和响应式布局。旧代码使用的 `create:false` + `drop` 单一写入方向正确；在旧 `dist`、独立端口和隔离浏览器中执行旧版真实鼠标拖拽流程，能从右侧创建任务、返回列表、连续拖入两次。

因此，目前证据只能证明“原始失败没有在本机复现”，不能证明是某个特定浏览器/缓存/生命周期故障。

已完成的修复与加固：

- 提取 `useTaskDrag`，用稳定 callback ref 跟随真实容器节点绑定/销毁；节点替换、详情返回和 StrictMode 不依赖一次 `useEffect([])` 对 ref 存续的假设。
- 使用委托选择器和可发现的点状手柄，不抢标题、完成按钮或列表滚动；默认时长读取最新设置。
- `create:false` 只绘制拖放预览，唯一 `drop` 回调事务创建关联块；同一原生 drop 事件去重，不同时走 eventReceive。
- 日/周创建具体时刻，月视图/全天区创建全天日期块；成功以 IndexedDB 提交为准，失败无持久/临时幽灵事件。
- 实测右侧周视图重复拖入、筛选/搜索/清单切换、折叠与详情重挂、日视图 90 分钟、月视图全天、配额写入失败和下一次重试；任务 ID、状态、截止日期保持。

### 2.2 重叠拥挤

已复现 08:00—23:00 长块与 08:30—09:45、08:30—10:00 两个短块并存时，中文标题逐字换行甚至超出块底。源码原因是 `slotEventOverlap=true` 允许前景覆盖，叠加 `overflow-wrap:anywhere` 和极窄列宽。

处理：普通前景 `slotEventOverlap=false`，不修改真实时间；标题单行省略、完整 hover/aria 提示。周视图优先显示开始时刻，日视图显示起止；“本段安排”提供所有事件完整标题/时间和编辑入口，三条以上重叠明确提示。窄列仍可能省略标题，可切日视图或用完整列表，不能让省略伪装成事件丢失。

独立日程新增 normal/background。背景为淡色范围，不占前景宽度；背景列表可编辑、删除或切回普通。背景隐藏只影响视觉，冲突检查仍按全部真实范围计算，包含隐藏清单和重复实例。重叠提示不阻止保存。

重复模型只存 event 系列：`frequency/interval/weekdays/startDate/localTime/durationMinutes/until/count` + IANA timeZone。实例 ID 为 `seriesId@occurrenceDate`，仅在可见日期范围派生；持久 ID 不变。例外单独记录 `seriesId/occurrenceDate/cancelled/replacement`。

- 一次最多展开 400 天/100000 实例；超限抛可诊断错误，不静默截断。

## 5. 数据迁移、安全与恢复

正式路径：原 Dexie v1 → `version(2).upgrade`，应用 JSON schemaVersion 1 → 2。

升级事务先用冻结 v1 schema 完整验证，再保留 `before-schema-v2` 原始快照并补新字段，不清空旧表、不更换稳定 ID、不重建用户库。新任务字段为 `subtasks=[]/tagIds=[]`，旧独立日程为 `display=normal`；主题、清单显隐、默认视图和布局保留，时间轴增加合理默认值。失败会回滚版本及所有表。

v2 新表：tags、exceptions、undo；原 lists/tasks/scheduleBlocks/metadata/tombstones/backups 保留。新增删除实体记录墓碑；子任务内嵌，由父任务 revision 跟踪。undo 是设备本地记录，不导出、不伪装为同步队列。

- v1 JSON 先验证、再纯迁移，v2 JSON 覆盖系列、例外、标签、子任务与新设置；未知版本拒绝。
- 完整替换前保存快照、二次确认，同一事务写入；失败不破坏旧数据。导入前最近 3 次快照轮换不删除升级前快照。
- 删除任务/安排撤销恢复原 ID 和关联，revision 递增；清除数据库中的对应墓碑，不能只改内存。冲突时不覆盖已有记录；原清单/标签已删时安全迁回收集箱并去掉无效标签。
- 新一次删除替换旧撤销入口，30 秒后失效；导入替换建立新状态并清除旧撤销。
- liveQuery 同时订阅内容与撤销，刷新/跨标签页不沿用失效按钮。已提交但随后读取失败会明确提示“已提交”，仍返回真实 ID，避免当成未保存再建一条。
- 启动/迁移异常时保留库并提供原始恢复导出，包含旧 backups；该恢复包是诊断原始表，损坏内容需修正后再按正常 schema 导入。
- 所有用户文本按 React 普通文本渲染，无不可信 HTML；没有 GitHub API、PAT、OAuth、远端同步或后端。

## 7. 已知限制与用户待验边界

- 用户原始“右侧不能拖入”尚未在本机复现；已有真实自动化覆盖可证明这些操作路径当前有效，不能替代用户实际浏览器复测。若仍失败，应提供浏览器、日/周视图、清单/筛选状态和手柄操作步骤继续定位。
- 已验证 Windows Chromium 与 390/768px 布局，不等于实机 Safari/iPhone/iPad；触摸长按、软键盘和系统存储策略仍需实机验收。
- 背景安排通过表单编辑，不支持 FullCalendar 原生背景拖动/拉伸；普通与任务块仍可拖动/缩放。周视图极多重叠时仍会省略文字，所有内容有完整列表入口。
- 重复只支持独立 event，不支持重复任务生成或子任务自动安排；没有“此后所有”编辑。单次取消不属于 30 秒删除撤销；可从系列管理调整/删除系列，取消记录随备份保留。
- 当前不提供取消记录的可视化逐项恢复、字段级例外继承、第二次 DST 回拨时刻选择、任意全局显示时区选择。整系列的既有完整替换例外优先于新系列内容。
- JSON 为安全完整替换，未实现合并导入；每次事务仍读取/校验完整快照，适合个人规模，未做超大数据压力测试。
- 首次离线使用仍需在线缓存生产构建。旧 Service Worker 可能继续服务已打开页面；升级时联网关闭旧页再重新打开同一地址。固定浏览器、协议、主机和端口，换来源需 JSON 迁移。
- 未实现 GitHub 授权/同步、重复任务、通知、统计、外部日历或完整 PWA/Pages 发布，均未声称完成。
