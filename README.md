# Polar Schedule

用时间轴安排日程，用自定义清单整理待办。免费、开源、纯前端。当前为 Phase 4（v0.4.0）：本地功能无须登录，可由用户主动连接固定的 GitHub 私有正式/测试数据仓库；支持 Pages 子路径部署、PWA 安装与离线使用。Dexie 保持 v4，领域 JSON 保持 v3，保留原有日程、备份和撤销。

发布状态及实际站点以 [Phase 4 验收报告](docs/PHASE4_REPORT.md) 为准。[最简使用指南](docs/PHASE4_USER_FINAL_STEPS.md) · [部署、迁移与恢复](docs/PHASE4_DEPLOY_AND_RECOVERY.md)。

## 安装与启动

需要 Node.js 22.12 或以上，推荐使用本次验证的 Node.js 24。已提交 `package-lock.json`。

```powershell
cd C:\Users\34201\Desktop\polar_schedule
npm ci
npm run dev
```

打开终端显示的地址，默认是 [http://127.0.0.1:5173](http://127.0.0.1:5173)。按 `Ctrl+C` 停止。

日常使用与离线验收建议使用生产预览：

```powershell
npm run build
npm run preview -- --port 4173 --strictPort
```

打开 [http://127.0.0.1:4173](http://127.0.0.1:4173)。第一次保持联网，打开“设置与数据”，确认显示“离线页面已就绪”。之后即使断网，刷新和重新打开这个地址也能编辑本地内容。开发模式不提供页面缓存，但已打开页面仍可离线写入 IndexedDB。

预览命令只提供静态文件，不是业务后端。`npm run build` 生成根路径预览的 `dist/`；`npm run build:pages` 单独生成 `/polar-schedule/` 子路径的 `dist-pages/`。Pages 工作流只发布后者，不改变原 4173 的地址或数据库。

**请固定使用同一浏览器、同一地址和端口。** `localhost` 与 `127.0.0.1`、5173 与 4173 是不同来源，各有独立数据库。切换时请先导出再导入，不能将空白页面误判为数据丢失。不要直接双击 `dist/index.html` 打开。

## 使用方法

- 左侧创建、选择和管理清单；“…”中可改名、颜色、图标、上下排序、显隐、归档及删除。收集箱不可删除、归档或改名。删除清单会确认并将其任务移到收集箱，安排保留。
- 清单、标签、日程共用圆角颜色选择器：预设、色相/饱和度与自定义 `#RRGGBB`。确认颜色只更新当前表单草稿，仍需保存表单；取消/Esc/点外部不改色，不打开系统原生 RGB 面板。
- 右侧添加任务，首屏编辑标题、整个任务状态和可选截止日期。描述/清单/优先级、标签、子任务按需展开；“描述与任务属性”中可上下排序。列表圆圈控制整个任务，“已完成”筛选下可撤销。
- 待办筛选支持未完成、未安排、已完成、未来 7 天内截止（含逾期）和全部。归档或隐藏清单不出现在总览；仍可从清单导航单独查看。
- 点击或拖选日历空白处，选择“新建日程”或“安排已有任务”；后者只引用现有 Task。拖动事件移动，拖动上下边缘调整时长。支持日、周、月及前后导航、今天、全天、跨日和重叠。
- 拖动任务卡片右侧的点状手柄到日历，默认添加 1 小时安排；也可点击“安排”或任务详情中的“保存并安排时间”。**再次安排创建另一个时间块，始终引用同一个任务。**
- 手柄在待办筛选、清单切换、详情返回和折叠重开后仍可使用。日/周视图按所放时刻创建，月视图和全天区创建全天安排。写入失败不留下临时事件，重叠只提示、不阻止保存。默认长度可在设置调整。
- 点击任务日历块直接编辑**本次安排**：起止时间、独立完成/撤销、删除此段、所属清单与第几段；“查看完整任务 / 修改任务属性”进入父任务。有未保存的改时会明确变成“保存并查看”入口。移动安排不改变截止日期，删除安排不删除任务。
- **整个任务完成与本次安排完成互相独立。** 同一任务可以一段已完成、另一段待执行；任务详情显示完成段数/总段数并逐段勾选。父任务完成不会改写安排记录；独立日程不附加勾选。这支持手动分次打卡，尚不自动生成周期任务。
- 已完成的执行段在日/周/月显示 `✓ 已完成` 和轻量底色，点击可撤销；待执行段与父任务状态不跟随变化，不再使用粗重虚线。
- 点击开始/结束输入框或日历图标，弹出统一迷你月历：月/年导航、24 小时、5 分钟快捷选择、精确分钟、确认、Esc 取消；也可键盘输入 `YYYY-MM-DDTHH:mm`。全天和截止日期只选日期，全天结束日期含当天。
- 日/周的全部日程使用 FullCalendar 标准前景并列，重叠时间互不覆盖，不设置自定义并列数量上限或分级标记栏。每条都可直接点击、拖动和拉伸；大量重叠时标题可截断，日期预览及“本段安排”提供完整标题、时间与编辑入口。
- 不再提供背景/普通模式和隐藏背景开关。旧 JSON 和数据库的 `display=background`、`showBackground` 字段兼容保留；原背景日程也按普通日程显示及编辑，改时不重写旧属性。
- 月视图将所有日程、任务、全天/跨日与重复实例显示为普通可点条目，过多时保留原生“+N更多”；遵守清单显隐/归档，不复制事件。月份内容较高时可自然滚动，不用滚轮跳月；更多列表固定标题、内部滚动，可查看末项。
- 点击月格日期数字或周视图日期标题，预览当天完整安排；跨日事件显示当天交集。点条目直接编辑，点“查看完整日视图 →”转到所选日期；点击空白仍新建安排。
- 顶部“跳转”共用迷你月历，支持输入 `YYYY-MM-DD`；月视图也支持 `YYYY-MM`。日视图到当天，周视图到其所在周（遵守周起始设置），月视图到所在月。跳转不更改安排。
- 独立日程支持每天、每 N 天、每周指定星期/每 N 周、每月同日重复，结束条件为日期（含当天）、次数或无限。重复只存一条系列和必要例外，不预先复制多年日程。
- 点击重复实例后选择“仅本次”或“整个系列”；单次改动是替换例外，单次删除是取消记录。拖动/拉伸重复实例只修改本次。整个系列修改保留已有例外；新规则不再匹配的例外不展示，仍随导出保留。要结束系列请设置结束条件或删除整个系列。“重复系列”入口可管理已结束或当前没有实例的系列。
- 任务可编辑和勾选子任务、调整子任务顺序，关联多个标签。父任务由用户手动完成，子任务不会自动成为日历事件。标签管理支持创建、改名、改色和删除；删除标签会移除任务关联。
- 待办支持标题/描述搜索，以及清单、状态、标签、截止区间组合筛选。可明确选择跨清单并包含隐藏/归档内容；搜索结果只影响待办，不改变日历可见性。
- 删除任务或独立时间块/整个系列后有 30 秒撤销入口，恢复原 ID 与关联；撤销会消除对应删除墓碑。只保留最近一次此类删除，导入替换后不能撤销旧操作。“仅本次取消”、清单删除和标签删除不在此撤销范围。
- 桌面底部可折叠清单/待办侧栏。手机默认日视图，以底部入口切换日程和待办，清单从左上角打开。所有主要流程均可通过表单完成。
- 全局设置仅在右上角；分为外观、日历与时间轴、清单与显示、数据备份与恢复、GitHub 同步、安装与更新，可用分组按钮快速定位。清单局部管理仍在各清单菜单。主题、默认视图、清单显隐、15/30/60 分钟粒度、可见小时、周起始、密度及默认时长仍保存；范围外内容不删除。
- 表单点击保存后才提交；即时操作会直接写入数据库。顶部“正在保存”结束后再关闭页面。写入未结束时会尝试用浏览器离开提示保护操作；强制结束浏览器仍可能中断最后一笔写入。

## 备份与恢复

数据库名为 `polar-schedule`，存储位置是当前网站来源的 IndexedDB；未主动启用同步时不向远端上传任务。浏览器清理数据、隐私窗口、磁盘或存储配额问题可能影响保留，请定期备份。

1. 在“设置与数据”点击“导出完整 JSON”，确认下载完成。
2. 恢复时选择 JSON。应用兼容 `schemaVersion: 1`、`2`、`3`，先用冻结旧校验器验证再迁移；检查必要字段、真实日期、时间区间、UUID、重复 ID、收集箱、标签/系列/任务引用，再显示导入摘要。导出统一为 v3。
3. 先导出当前内容，点击“继续替换导入”，在第二次确认中执行替换。
4. 原内容会先保存在数据库内；最近 3 次导入前快照保留。点击“下载最近一次导入前备份”，再从普通导入入口恢复。
5. 格式错误或写入失败会保留原数据；事务失败时备份与替换一起回滚。内部快照会随浏览器数据清理而消失，不能替代独立下载的文件。

已有 Phase 2 数据通过 Dexie `version(3).upgrade` 原库升级，不清库：原始 v2 快照保留为 `before-schema-v3`，旧任务安排默认 `pending`，ID、原时间戳、标签、系列、例外、设置及旧备份保留。Phase 1 依次走 v1→v2→v3，另保留 `before-schema-v2`。迁移快照不参与最近 3 次导入快照轮换。失败时整个版本事务回滚，启动错误页可导出原始数据（含旧备份表）。升级前建议先在原浏览器导出独立 JSON，关闭旧页后在同一地址重新打开新版；无需清除网站数据。

当前采用完整替换导入，尚无合并导入。

## 技术结构

React + TypeScript（严格模式）+ Vite；FullCalendar **免费标准** React / timeGrid / dayGrid / interaction 插件；Dexie + IndexedDB；Zod 运行时校验；Lucide 图标。

为减少不必要依赖，采用 CSS 变量与原生表单、`dialog`，不引入 Tailwind/shadcn 组件体系。状态由 React Context 与 Dexie `liveQuery` 管理，跨标签页数据库变化可以更新界面。

```text
src/app/                应用布局、状态订阅、操作反馈
src/components/         按钮、对话框、DayPicker 日期时间 / react-colorful 颜色选择器
src/domain/             冻结 v1/v2 与当前 v3 校验、迁移、日期/时区、重复展开、筛选
src/storage/            IndexedDB v4、领域 JSON v3、事务 CRUD、升级/导入/同步快照、撤销
src/sync/               固定测试/正式仓库 API、稳定快照、三方合并、同步状态、专用凭据层
src/hooks/              跟随实际容器节点生命周期的外部任务拖拽
src/features/calendar/  FullCalendar、月投影、当天预览、时间表单、拖拽与缩放
src/features/lists/     清单导航与管理
src/features/tasks/     待办筛选、任务详情、关联安排
src/features/settings/  主题、显隐与 JSON 备份恢复
src/features/sync/      唯一设置内的授权、首次确认、冲突和顶部轻量状态
scripts/build-sw.mjs    生产版最小静态资源离线缓存
src/features/pwa/      安装、更新状态与新 origin 迁移引导
.github/workflows/     main 验证、Pages artifact 与正式部署
e2e/                    浏览器关键交互验收
```

Task 与 ScheduleBlock 独立，通过 `taskId` 关联；时间块不复制任务标题。task 型块包含 `executionStatus: pending|completed`，完成时带 `completedAt`，event 不含执行状态。普通安排使用 UTC ISO 8601 + 创建时 IANA 时区；界面跟随当前浏览器时区。截止日期使用 `YYYY-MM-DD`；全天使用 `[startDate, endDate)`。每个顶层实体保留 UUID、revision、createdAt、updatedAt，删除写入 tombstone。IndexedDB 结构版本为 4，领域 JSON schemaVersion 为 3，兼容 v1/v2 导入，未知版本拒绝。标签和重复例外单独存储，子任务嵌入父任务；凭据、同步元数据、备份和撤销不进入普通导出或远端快照。

月历界面采用 React DayPicker（内部使用日期库），领域转换仍使用 Date/Intl。纯日期运算按 UTC 日历进行，本地输入往返校验拒绝不存在时间。重复规则保存系列当地日期/钟点、IANA 时区和墙上持续分钟，按当前视图展开；每 N 周以开始日期所在周的周一锚定，月末不存在日期跳过且不消耗次数。重复遇夏令时跳时按时差前移，回拨取较早一次。显示时区仍跟随浏览器，系列时区可单独填写。

## 当前限制

- 同步只开放 Polar0216 的两个固定私有仓库，不支持任意仓库。没有通知、统计、多用户或外部日历。口令加密模式尚未实现，可信设备模式须主动同意保存可用凭据。
- 暂无重复任务或子任务单独安排。重复系列不提供“此后所有”，只提供“本次/整个系列”。
- 合并导入、任意显示时区选择、夏令时回拨第二次时间选择、大数据量增量写入优化待后续处理。每次事务读取并校验完整本地快照，适合个人规模。
- 一次重复展开最多 400 天/100000 个实例，超限明确报错，不静默截断；日/周/月常规视图均在此范围内。
- 离线重新打开需要先成功缓存生产构建；首次从未访问过的网站无法离线下载。缓存更新在旧页面关闭后生效，更新版本时请联网关闭旧页面再重新打开。
- 已用 Windows Chromium 自动化验证；真实 iPhone/iPad Safari、触摸长按拖拽、系统级存储回收和长期使用仍需实机确认。

## GitHub 私有同步

从唯一「设置与数据 → GitHub 同步」配置，或点顶部轻量状态进入同一分组。默认仍为测试环境 `Polar0216/polar-schedule-data-test`；正式环境须明确切换为 `Polar0216/polar-schedule-data`。两者仅允许 main / `data/polar-schedule.json`，验证仓库身份、私有性与分支。切换或换 PAT 停止当前同步，保留本地内容与备份，重新预览，不能沿用另一绑定的共同祖先或 SHA；首次确认前不上传或替换。不同记录可自动合并；同记录竞争暂停，先导出两端、选择后确认。断开只清凭据，不删除日程。

“记住此设备”默认关闭；主动勾选后持久保存可用 PAT，不宣称加密或能防恶意扩展/XSS。同账户 GitHub Pages 项目属于同一 origin，路径不能隔离 IndexedDB/localStorage 凭据；只在可信设备和可信同源项目下选择记住。需要仅正式数据仓库 Contents 读写权限的 fine-grained PAT，由用户本人在网页输入，到期重新授权。普通 JSON 与远端内容均无凭据。详见 [同步设计](docs/PHASE3_SYNC_DESIGN.md) 和 [正式使用步骤](docs/PHASE4_USER_FINAL_STEPS.md)。

`npm run verify:mocks` 串行执行 Phase 4 全部门禁并记录源码指纹。Phase 3 实网脚本仍保留，仅允许测试仓库，另需 `node scripts/verify-mocks.mjs` 生成匹配的 Phase 3 门禁。Phase 4 不需要读取测试 PAT，不对真实正式库执行联调；真实联调的历史结果见 Phase 3 报告。
